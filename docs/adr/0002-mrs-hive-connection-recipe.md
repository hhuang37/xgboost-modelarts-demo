# 0002: A fixed recipe for connecting to this MRS cluster's Hive from Python

The MRS 8.6 cluster runs HiveServer2 with Kerberos (fixed Huawei-style SPN `hive/hadoop.<system-domain-lowercase>@<REALM>`, KDC on port **21732**, not 88) and `qop=auth-conf`, so stock `hive.connect(auth='KERBEROS', ...)` cannot work — it derives the SPN from the TCP host. Decision: every Python client in this repo that reaches Hive uses the measured recipe (implemented in `hive_export/test_hive_conn_mrs.py` for cluster nodes and `hive_export/modelarts_hive_conn.ipynb` for ModelArts notebooks): a custom `thrift_transport` that decouples the TCP host from the SASL/SPN host, the cyrus `sasl` pip package as GSSAPI binding, a krb5.conf with `dns_canonicalize_hostname=false` and KDC port 21732, and a kinit beforehand. Cluster-specific values (IPs, SPN, ports) have a single source of truth in `hive_export/MRS_RUN.md §0` — reference it instead of duplicating.

Considered options: pure-sasl + pykerberos (rejected — measured on 2026-08-19: SASL negotiation succeeds all 5 steps, then fails at the auth-conf privacy wrap of the first request with "Invalid token was supplied"); beeline/JDBC via the MRS client (rejected — works, and is the cross-check tool of choice, but is not Python-native for notebook/training code).

Consequences: the pip `sasl` package is a C/C++ extension, so root/sudo environments need gcc/g++ + libkrb5-dev + libsasl2-dev + libsasl2-modules-gssapi-mit (apt) before `pip install`; root-less environments such as ModelArts notebooks (running as `ma-user`) instead install the prebuilt conda-forge `krb5` (ships `kinit` in `$CONDA_PREFIX/bin`) and `sasl` packages, with a GSSAPI-plugin functional self-check in `modelarts_hive_conn.ipynb` cell 3 (create a cyrus `sasl.Client`, `setAttr(host, service)`, `init()`, then `start("GSSAPI")`: "No worthy mechs" means the plugin is missing; a credentials/KDC error only means no ticket yet). Note: the cyrus `sasl` package has **no mechanism-listing API** — `available_mechs()` belongs to pure-sasl and raises `AttributeError` on cyrus (caught on ModelArts 2026-08-20). KDC reachability on 21732 is a hard prerequisite alongside HiveServer2 21066; and do not "simplify" client code back to `auth='KERBEROS'` — it cannot connect to this cluster. TGTs expire after 24h, so long-lived consumers should re-kinit (keytab preferred).
